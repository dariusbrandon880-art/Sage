# SAGE Control Tower — C2 Execution Contract

Status: GOVERNED / ACTIVE

## Purpose

The Control Tower is the C2 control plane for **Five-Mission SAGE/SAGI growth waves**.

A Five-Flight wave is not five fixed subsystems and is not synonymous with the historical 003–007 longitudinal campaign. The Director supplies five consequential missions/frontiers. C2 binds each mission to the full SAGE capability stack and advances all five concurrently when their evidence boundaries permit.

## C2 role

GPT/C2 owns intelligence work: repository recon, external Super Search, frontier binding, decision, authorization boundary, execution orchestration, observation, independent verification, and compounding.

The execution substrate is not the brain. GitHub Actions, local/runtime tools, MCP tools, and other execution surfaces are hands used by C2 when available; the Master Archive/repository remains canonical validated truth.

## Mission input

A Five-Mission wave contains exactly five Director-authorized mission statements. Examples may be Google, Sports, CP3, or any other consequential frontier; names are mission labels, not permanent architecture lanes.

For each mission C2 records:

- mission identity and objective;
- current repository baseline;
- smallest consequential frontier;
- success/verification criteria;
- safety, authorization, and evidence boundaries;
- dependencies and shared invariants;
- Super Search findings and their classification;
- build/repair trajectory;
- observable evidence and final verification result.

## Full-stack flight law

Every flight may use the **entire SAGE/SAGI stack**. A mission is not restricted to one technical layer or domain.

Each flight follows:

**SENSE → RECON → SUPER SEARCH → BOUND → DECIDE → AUTHORIZE → LARGE BUILD → TEST → OBSERVE → REPAIR/RERUN → VERIFY → PROMOTE → COMPOUND**

The Large Build is one coherent governed campaign containing all causally connected changes needed to close the bounded frontier. Independent work is parallelized; shared invariants remain serialized at their authority boundary.

## Five × 20 growth law

Five flights are five concurrent evolutionary trajectories across the full growth surface. The "20" is a growth-budget/frontier model, not twenty permanently assigned features.

Each flight can traverse whichever capability dimensions are consequential to its mission. Improvements discovered in one flight become candidate reusable knowledge for the other flights after validation.

**5 × 20 = five missions × twenty-dimensional growth capacity, with cross-flight compounding.**

The exact internal twenty-dimensional map remains governed by the Master Archive/repository. The Control Tower must not invent or silently replace that map with an external taxonomy.

## Super Search law

Super Search is mandatory for consequential frontiers and operates across all five flights.

Search broadly enough to challenge the current approach across relevant domains, including agent/runtime architecture, memory, evaluation, security, distributed systems, mathematics, statistics, information/control theory, optimization, formal methods, biology/neuroscience, robotics, reliability engineering, scientific discovery, standards, patents, open source, and practitioner evidence when materially relevant.

External findings are classified **KNOWN / TRANSFERRED / HYPOTHESIZED**. External intelligence can challenge or improve a build but never becomes canonical without repository/Master Archive validation.

## Parallel-first law

The five flights run concurrently whenever their environments, state boundaries, authority boundaries, and evidence are independent enough to prevent races or ambiguity.

Within each flight, independent discovery, implementation, testing, adversarial evaluation, evidence analysis, and bounded repair also run concurrently where safe.

A failure in one flight does not stop healthy flights. C2 preserves the failure evidence, identifies the smallest shared consequential cause when supported, repairs the shared boundary once, reruns affected paths, and continues healthy paths.

Hard stops remain mandatory for authorization, safety, provenance, canonical-state corruption risk, ambiguous telemetry, or evidence insufficiency.

## Cross-flight compounding

Validated output from any flight is immediately eligible as candidate input to the other four, subject to the same validation boundary.

The shared learning pattern is:

**discover → preserve → reason → build → verify → persist → reuse → compound**

Cross-flight reuse must preserve provenance, attribution, negative knowledge, and the distinction between candidate and validated knowledge.

## Historical 003–007 campaign

The existing 003–007 Horizon / Recovery / Reuse / Retention-Regression / Compound campaign remains a **specific empirical campaign and reusable production flight implementation**. It is not the universal semantic definition of Five-Flight.

Existing runners may be reused when they match a mission's bounded objective. The Control Tower must not create duplicate execution systems merely to rename the historical campaign.

## Invariants

- Exactly five missions per Five-Mission wave.
- Repository/Master Archive truth outranks conversational state and external research.
- Recommendation is not authorization.
- Tests are not capability claims.
- Missing or ambiguous evidence is HOLD.
- Observation collection must not silently mutate canonical state.
- Parallel paths remain evidentially separable until reconciliation.
- Failure evidence is retained.
- Closed findings are not reopened without new evidence.
- No fabricated telemetry, learning quality, recovery, retention, or capability result.
- No unrelated expansion merely because a large build is authorized.
- C2 independently verifies each flight and the combined wave before promotion.

Separate model surfaces are not treated as secretly connected. The Control Tower is a system protocol, not role-play.

## Completion gate

A Five-Mission wave is complete only when all five missions have:

1. a bounded consequential frontier;
2. completed the required build/repair trajectory;
3. produced observable evidence;
4. passed mission-specific verification;
5. preserved durable provenance/receipts; and
6. been independently reviewed by C2 at the combined-state boundary.

Only then may validated results compound into canonical state.

## STOP boundary

Do not stop merely because the wave is large, multi-domain, or encounters an ordinary engineering failure. Continue through bounded repair and rerun while invariants remain intact.

Stop/HOLD only at a genuine authorization, safety, technical, provenance, or evidentiary boundary, or when the current frontier has been verified and the next frontier requires a new consequential decision.
