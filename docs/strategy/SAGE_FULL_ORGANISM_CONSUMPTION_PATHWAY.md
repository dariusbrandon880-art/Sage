# SAGE Full Organism Consumption Pathway

**Directive ID:** `SAGE_FULL_ORGANISM_CONSUMPTION_PATHWAY`
**Status:** Strategic pathway guide
**Authority:** Subordinate to SAGE Constitution, Master Archive, canonical Jigsaw architecture, and live repository truth.

## Purpose

SAGE must treat consequential concepts, research, failures, business hypotheses, architecture ideas, external intelligence, and repair lessons as inputs to one governed organism—not as isolated notes or chat-local context.

This document is a **pathway guide**, not a second source of truth. Canonical implementation, validated state, evidence, and authorized promotion remain authoritative wherever they already live.

## Core pathway

`DISCOVER → CLASSIFY → LOCATE → CROSS-LINK → RECON → HYPOTHESIZE → EXPERIMENT → ADVERSARIAL VERIFY → VALIDATE → PROMOTE/REJECT → ARCHIVE/COMPOUND → NEXT FRONTIER`

For consequential engineering or repair work, use the stronger repair loop:

`REPO TRUTH → HISTORICAL RECON → ROOT CAUSE → ATTACK → REPAIR → REGRESSION → FULL VERIFY → EXACT-SHA RECONCILIATION → PERMANENT LEARNING → COMPOUND → NEXT ATTACK SURFACE`

The execution discipline for that loop is defined by `docs/governance/SAGE_BIG_JUMP_WAVE_HARDENING_PROTOCOL.md`.

## Full Organism Consumption rule

For every consequential new concept, C2 must determine:

1. What real problem or capability does it represent?
2. Which existing organism organ owns it?
3. Is it CORE, SERVICE, PROJECTION, or EVIDENCE_LEARNING?
4. Which existing architecture, business model, research track, or blueprint does it connect to?
5. What prior SAGE work, repair lesson, failed hypothesis, or negative evidence must be consulted first?
6. What external evidence could corroborate or falsify it?
7. What measurable experiment would distinguish useful capability from attractive narrative?
8. What evidence is required for validation?
9. What existing promotion boundary would authorize durable adoption?
10. What reusable capability, test, receipt, documentation, or defensive guard remains afterward?
11. What new attack surface or dependency does the change create?
12. What is the highest-value next frontier after the result?

## Repair learning is an organism input

A consequential repair is not consumed when the code is fixed. The organism must consume the **failure, reasoning, attack method, proof quality, repair, regression, and resulting invariant**.

`FAILURE → SIGNAL → ROOT CAUSE → ATTACK VECTOR → REPAIR → PROOF → REGRESSION → EVIDENCE → INVARIANT → REUSABLE REPAIR PATTERN → NEXT ATTACK`

The reusable repair pattern should explain how future C2/engineering work should recognize and handle the same failure class. Examples include:

- start from live repo truth rather than a completion narrative;
- retrieve prior repair history before designing the next repair;
- attack security/governance tests for vacuous assertions;
- require precondition → violation → rejection → unchanged postcondition for rejection tests;
- repair canonical boundaries instead of weakening governors or patching presentation symptoms;
- reconcile code, evidence, and exact SHA before promotion;
- retain rejected paths and near misses as negative evidence;
- immediately convert newly exposed seams into the next bounded attack surface.

The goal is not autonomous authority. The goal is **autonomous reuse of validated repair knowledge inside the existing governance architecture**.

## Autonomous repair-learning pathway

When a consequential repair completes:

1. Capture the failure and detection signal.
2. Retrieve relevant historical repairs and identify matching patterns.
3. Record the root cause and attack vector.
4. Record the repair and why it strengthens the canonical boundary.
5. Require regression and adversarial proof.
6. Bind evidence to the exact implementation SHA and verification result.
7. Extract a reusable repair pattern.
8. Validate that learning through the existing governance/archive lifecycle.
9. Persist it in the canonical repair-history surface.
10. Feed the pattern into future recon and attack planning.

No model, agent, receipt, or learning record may self-promote itself into canonical authority. Learning remains subject to the same state, provenance, evidence, and validation boundaries as every other consequential knowledge input.

## External intelligence protocol

Super Search / external research is a sensing layer, never canonical authority.

Research should intentionally sample both large and small organizations, startups, open-source projects, researchers, practitioners, technical talks, podcasts/video discussions, postmortems, benchmarks, and credible failures when relevant.

External material is used to:

- discover missing patterns;
- challenge assumptions;
- identify alternative implementations;
- find failure modes;
- compare operational tradeoffs;
- establish baselines;
- falsify SAGE hypotheses.

External claims become SAGE candidate knowledge only after repository-side validation through the existing research → experiment → validation → archive lifecycle.

## Organism alignment map

### CORE
C2, SageRuntime, constitutional contracts, state authority, mission/governance boundaries.

### SERVICE
Super Search, bounded research probes, specialist execution, external intelligence adapters.

### PROJECTION
ChatGPT immersion, Observatory HUD, customer surfaces, reports, progression displays.

No fifth organ category and no duplicate C2, state, or workflow authority may be introduced merely to house a new idea.

## Business + research + architecture convergence

Every mature concept should be cross-linked across three dimensions before promotion:

`CAPABILITY → ARCHITECTURE → ECONOMIC/USER VALUE`

A technically elegant capability without a meaningful problem is a research candidate. A valuable business idea without a validated technical mechanism is a hypothesis. A working implementation without evidence and governance is not durable SAGE capability.

The organism seeks the intersection:

`REAL NEED + TECHNICAL FEASIBILITY + GOVERNED EXECUTION + MEASURABLE VALUE + REUSABILITY`

## Creative frontier handling

Names, metaphors, fictional systems, and conceptual frames—including future SAGE X, Star Wars-inspired internal metaphors, or other internally named research programs—are treated as **frontier hypotheses** until translated into concrete capability claims.

The process is:

`CONCEPT → IMPLIED CAPABILITY → RESEARCH QUESTION → EXPERIMENT → EVIDENCE → VALIDATED CAPABILITY OR REJECTION`

The metaphor never becomes authority merely because it is compelling.

## Hardening → invention transition

SAGE operates two coupled modes:

**HARDEN:** strengthen governance, reliability, persistence, provenance, recovery, runtime boundaries, and repair intelligence.

**INVENT:** open validated frontiers and investigate capabilities that the hardened substrate now makes possible.

The transition is not a one-time switch. Invention continues while a protected hardening lane attacks newly discovered seams.

Strategic trajectory:

`STABILIZE → COMPOUND → OPEN FRONTIER → INVENT → VERIFY → EVOLVE`

## Big Jump Wave operating rule

A Big Jump Wave is a capability-hardening cycle, not a PR-counting mechanism. Start from exact repository truth, consult historical failures and repair patterns, use external intelligence to falsify assumptions, map bypass surfaces, make the smallest high-leverage canonical change, attack both the implementation and its proof, run full verification, reconcile the exact SHA, permanently log the learning, and immediately identify the next attack surface.

The five-flight operating pattern is:

`F1 RECON → F2 FALSIFY → F3 REPAIR → F4 RED TEAM → F5 EVIDENCE/COMPOUND`

Parallel work is permitted only where ownership boundaries do not collide. Shared canonical state and transitions are sequenced.

## Historical learning requirement

Before consequential repair or architecture work, inspect prior repair logs, relevant evidence, rejected hypotheses, and previous implementation patterns when available.

After the work, permanently record:

`ROOT CAUSE → ATTACK → REPAIR → TEST → ADVERSARIAL RESULT → INVARIANT → REUSABLE PATTERN → REMAINING GAP`

A repair that is not converted into reusable learning is incomplete from an organism-growth perspective.

## Anti-drift rules

- Do not duplicate existing canonical systems.
- Do not promote research because it is interesting.
- Do not treat external research as repository truth.
- Do not treat presentation as authority.
- Do not allow model output to self-authorize canonical transitions.
- Do not claim capability from narrative completion reports.
- Do not erase negative evidence or rejected hypotheses.
- Do not optimize for feature count, points, badges, or PR count over verified capability.
- Do not stop at implementation; trace the change through evidence, validation, business value, and reuse.
- Do not accept stale authorization for a state-changing effect.
- Do not rely on a single enforcement point for critical governance invariants when layered checks are practical.
- Do not record repair learning without enough evidence to distinguish a real repair from a passing narrative.
- Do not allow the repair-learning mechanism itself to become an authority side door.

## Success condition

The pathway is working when a fresh C2 session can take a consequential idea or failure and trace it through the organism without reconstructing the reasoning from chat history:

`EXTERNAL/INTERNAL INPUT → CANONICAL LOCATION → HISTORICAL CONTEXT → RESEARCH/DESIGN → BUILD/EXPERIMENT/REPAIR → ATTACK → VERIFY → VALUE MEASUREMENT → VALIDATION → PROMOTION/REJECTION → PERSISTED LEARNING → NEXT FRONTIER`

> **Consume the idea. Consume the failure. Connect both to the organism. Test them against reality. Keep what survives. Turn the survivor into reusable capability. Make the next wave start smarter.**
