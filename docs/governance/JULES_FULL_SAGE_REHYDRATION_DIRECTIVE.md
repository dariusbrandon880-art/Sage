## 12. POINT ECONOMY

The working candidate model is:

`OBSERVABLE WORK → OUTCOME SCORE → POINTS → VERIFIED POINTS → XP CONVERSION → CAREER XP → PROMOTION ELIGIBILITY`

Candidate baseline conversion:

**10 verified Points = 1 Career XP.**

This is a candidate economy until validated through the actual repository implementation and evidence.

Points should be generated from observable verified outcomes, then weighted by factors such as:

- difficulty
- verification strength
- impact
- reuse
- frontier novelty
- coordination complexity

Candidate point bands for calibration only:

- 1–5: micro verified contribution / evidence hygiene
- 10: standard verified action
- 25: meaningful bounded outcome
- 50: substantial sortie result
- 100: independently verified mission-level outcome
- 250: reusable capability
- 500: major cross-system capability / frontier advancement
- 1,000+: exceptional breakthrough, requiring strict verification

Do not implement these numbers merely because they appear here. Calibrate against actual event classes and mission duration.

Anti-farming requirements:

- no evidence = no points
- no unique verified-event reference = no points
- same verified event cannot be replayed for progression
- quality weighting matters
- repeated trivial work has diminishing career value
- model text cannot award itself XP
- qualification evidence cannot be fabricated by the evaluated agent
- revoked/falsified evidence must be able to invalidate downstream progression claims
