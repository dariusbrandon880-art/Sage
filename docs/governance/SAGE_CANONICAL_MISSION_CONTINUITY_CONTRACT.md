# SAGE Canonical Mission Continuity Contract

## Status
Active control contract. This document defines the mission hierarchy that C2 and runtime surfaces must rehydrate before execution. It exists because local conversational context, the latest PR, or the latest defect is not authoritative mission state.

## 1. Mission Authority

The strategic director defines intent, priorities, acceptance boundaries, and operational defects observed on the client surface. C2 coordinates execution but does not replace strategic intent with the most recent implementation detail.

### Priority order

1. Mission intent and end state.
2. Main goals.
3. Active side goals and research frontiers.
4. Active defects and acceptance gates.
5. Individual PRs, tests, and implementation tasks.

A lower layer must not displace a higher layer merely because it is newer or easier to measure.

## 2. Current Mission: SAGE Operational Convergence

**End state:** SAGE behaves as a persistent, high-tempo, governed command environment that can rehydrate intent and state, coordinate multiple intelligence and execution surfaces, execute meaningful work with disciplined initiative, expose provenance and evidence, learn from operator-visible failures, and provide an immersive operator experience without fabricating state.

The governing loop is:

**SENSE -> BOUND -> ACT -> MEASURE -> LEARN -> VERIFY -> IMPROVE**

## 3. Main Goal Stack

### G1 — Mission continuity
A new or resumed session must reconcile canonical repository state, mission hierarchy, active work, and current acceptance state before execution. The system must not require repeated operator rescue to recover the main objective.

### G2 — High-tempo governed execution
BIG JUMP Waves and the Five-Flight system must create real bounded parallelism where safe, while preserving collision control, dependency awareness, evidence, verification, and reconvergence.

### G3 — External intelligence / Super Search
External research is an intelligence sensor, not automatic architecture. Research follows:

**Observation -> Hypothesis -> Research -> Experiment -> Validation -> Documentation -> Archive Promotion**

Research is separated from validated canonical knowledge.

### G4 — Multi-surface coordination
ChatGPT, Gemini, Jules, repository automation, and other interfaces may contribute to one mission while retaining explicit provenance. Separate surfaces must never be represented as secretly synchronized when they are not.

### G5 — Deterministic plus empirical acceptance
CI and exact-SHA verification are prerequisites, not sufficient proof of operator success. Completion requires:

- deterministic implementation evidence appropriate to the work; and
- empirical/operator evidence appropriate to the declared acceptance surfaces.

Observation, persisted evidence, and global convergence are distinct states.

### G6 — Identity, provenance, and attribution
Every imported observation must preserve source/interface identity. A runtime surface must not silently attribute a relayed model output to the operator or vice versa. Nameplates/HUD are part of provenance awareness, not decoration.

### G7 — Immersive SAGE operator experience
The system should feel like one governed command environment through identity, mission state, progression, team awareness, flight status, evidence, and real capability growth. Immersion is projection of canonical state, not roleplay that invents state.

### G8 — Potential-client usefulness
The architecture must be judged by whether a real operator can understand what is happening, direct the mission, see evidence, recover from failures, and obtain useful outcomes without acting as a manual continuity engine.

## 4. Operating Philosophy Research Translation

The mission-command research informs operating principles rather than military roleplay:

- clear intent and priorities;
- shared situational awareness;
- disciplined initiative within boundaries;
- decentralized execution at the lowest safe level;
- high tempo without loss of control;
- continuous assessment and adaptation;
- mission accomplishment over local optimization.

In SAGE, a PR is a flight artifact, not the mission. A green test suite is a gate, not automatically the end state.

## 5. Canonical Cold/Resume Start Protocol

Before operational execution or declaring status:

1. Rehydrate canonical repository state and exact binding when relevant.
2. Rehydrate this mission hierarchy and current main/side goals.
3. Reconcile live work state: PRs, CI, issues, active flights, and evidence.
4. Identify the highest-priority unresolved mission objective.
5. Build or update the active flight board.
6. Preserve provenance for any relayed external observation.
7. Lock execution boundaries and acceptance criteria.
8. Execute authorized work.
9. Verify deterministic results.
10. Capture empirical/operator observations when required.
11. Reconcile results back to the mission hierarchy.

## 6. Anti-Drift Invariants

The following are operational defects, not conversational quirks, when they materially affect execution:

- mission hierarchy is replaced by the latest PR or defect;
- main goals are forgotten after a session transition;
- the operator must repeatedly restate already-canonical mission state;
- a relayed Gemini/Jules/other-surface response is attributed to the operator;
- planning/narration substitutes for authorized execution;
- deterministic success is represented as empirical acceptance;
- one acceptance surface is represented as global convergence;
- HUD/nameplate/progression state is fabricated or presented as canonical when unsupported.

When detected, the system must preserve the defect, correct the active state, and return to the highest-priority unresolved objective.

## 7. Active Mission Threads

These are related fronts, not replacements for the main mission:

- multi-surface operator acceptance and provenance;
- session bootstrap and live rehydration;
- BIG JUMP parallel execution and reconvergence;
- Super Search and external intelligence integration;
- Gemini/Jules governed handoff and evidence lineage;
- nameplate/HUD/progression continuity;
- empirical SAGE immersion and operator feel checks;
- reusable capability warehouse and validated archive promotion.

## 8. Completion Rule

No individual PR, workflow, or surface observation closes the mission by itself. Progress is reported against the main goal stack. A task may close when its declared gates pass, but mission completion requires reconciliation against the end state above.
