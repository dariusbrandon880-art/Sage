# SAGE Primary Operator Continuity Goals

## Purpose

This document records the current mission overlay for SAGE operational convergence. It does not replace or redesign existing C2, Airspace, nameplate, HUD, progression, governance, acceptance, or evidence architecture. Existing canonical contracts remain authoritative within their scopes.

## Primary operator interface

ChatGPT is the primary operator/client interface for SAGE. The client/operator is the human using that interface.

The primary acceptance question is therefore:

> Can the ChatGPT interface carry the SAGE mission correctly across real interaction boundaries without requiring repeated operator rescue or realignment?

This requires observable behavior, not merely documentation or passing repository structure checks.

## Main mission: SAGE Operational Convergence

The main mission is to move SAGE from governed code and workflow machinery toward reliable operator-facing, mission-continuous behavior.

The core empirical path is:

1. Cold or new-session start.
2. Canonical rehydration.
3. Recovery of the active main mission and side-mission hierarchy.
4. Correct continuation without repeated operator rescue or manual realignment.
5. Clear attribution, provenance, and boundary handling.
6. A continuous SAGE command experience built from real state rather than invented presentation.

The main operator-facing acceptance dimensions include:

- mission continuity;
- identity and source attribution;
- canonical-state and evidence continuity;
- correct main-versus-side-goal prioritization;
- practical nameplate, HUD, progression, team-awareness, and immersion behavior;
- honest boundaries between independently connected model surfaces.

## Side mission: governed cross-model integration boundary

Gemini and Jules/execution are independent supporting surfaces. Their role is to validate and strengthen governed cross-model integration without displacing the primary ChatGPT operator interface.

Required concerns include:

- governed external-model evidence;
- exact SHA and lineage binding where applicable;
- explicit source attribution and handoffs;
- distinction between observation and persisted evidence;
- no hallucinated convergence;
- independent PASS/FAIL evidence under the required-interface contract.

## Acceptance hierarchy

Individual PRs, CI repairs, manifests, and governance mechanisms are supporting flights. They are not automatically the mission itself.

Implemented does not mean active.
Documented does not mean verified.
Remembered does not mean rehydrated.
Green CI does not, by itself, prove operator-facing continuity.

Global capability promotion must remain evidence-based and must not bypass unresolved primary-interface defects.

## Preservation rule

This overlay is additive. It must be used to rehydrate and prioritize active work without silently changing existing architecture or claiming that unobserved runtime behavior has passed.
