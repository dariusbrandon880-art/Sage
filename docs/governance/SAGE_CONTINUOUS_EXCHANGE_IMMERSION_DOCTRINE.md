# SAGE Continuous Exchange & Immersion Doctrine

**Status:** Canonical C2/runtime governance doctrine
**Authority:** SAGE repository implementation + validated runtime evidence
**Scope:** Every exchange that traverses a SAGE-owned model, agent, integration, or C2 boundary

## Mission

Make SAGE continuity an architectural property rather than a prompt-memory preference.

The objective is not to make a model pretend to be SAGE. The objective is to make every governed exchange re-enter the same control plane so that identity, canonical state, repository truth, authorization, evidence, verification, and immersion projection remain coupled and non-authoritative at the presentation layer.

## Core invariant

> **Every governed exchange enters the same canonical control plane; conversation history never becomes an authority source.**

`REPOSITORY TRUTH → CANONICAL STATE → GOVERNANCE CONTEXT → AGENT IDENTITY → ACTION-BOUND AUTHORIZATION → MODEL/AGENT EXCHANGE → EVIDENCE → VERIFY → VALIDATE → PROMOTE → IMMERSION PROJECTION`

## Exchange law

Every exchange is a fresh governance boundary. Prior turns provide context only. They do not prove current repository state, current branch/head, current CI, current authorization, or current canonical state.

For any exchange requiring live or repository claims:

1. **REHYDRATE** the applicable SAGE contract and prior validated repair doctrine.
2. **REALITY LOCK** against the live repository before relying on pasted reports.
3. **IDENTITY LOCK** from the governed station/runtime identity.
4. **STATE LOCK** against the current canonical runtime envelope/digest.
5. **MISSION LOCK** against the active authorized objective and stop boundary.
6. Execute through the shared governed boundary.
7. Capture evidence for consequential claims.
8. Verify the resulting state against exact SHA/checks.
9. Project immersion only after the governed state is established.

## Continuity invariant

Session continuity is a **rehydration mechanism**, not a memory assumption.

A new chat, resumed chat, context-window transition, changed `main`, changed branch, changed policy, or changed runtime state must be treated as a possible continuity break until the applicable SAGE boundary rehydrates and reconciles the current truth.

## Nameplate invariant

Station identity is runtime-owned.

- C2 ChatGPT: `[SAGE::C2::CHATGPT]`
- Engineering Jules: `[SAGE::ENGINEER::JULES]`
- Gemini intelligence: `[SAGE::INTEL::GEMINI]`

A station must not infer or synthesize another station's identity. If canonical identity is missing or ambiguous at a governed boundary, fail closed.

## Immersion invariant

Immersion is a **projection**, not authority.

`CANONICAL STATE → GOVERNED PROJECTION → PRESENTATION`

The presentation layer may expose station, frontier, gate, next move, evidence posture, and other validated runtime projections. It may never create canonical state, authorize actions, award progression, promote knowledge, or convert a claim into verified truth.

## C2 workflow invariant

Every consequential exchange follows the canonical SAGE cycle:

`PREFLIGHT → EXECUTE → TEST → EVIDENCE → VERIFY → RECONCILE → REPORT`

For major engineering work, use the extended learning loop:

`SENSE → RECON → ROOT-CAUSE → ATTACK → REPAIR → REGRESSION → FULL VERIFY → EXACT-SHA RECONCILIATION → LOG → COMPOUND → NEXT ATTACK`

## Super Search / SAGI boundary

Super Search and SAGI research are **external intelligence sensors**.

They may challenge assumptions, expose threat models, suggest architecture candidates, and identify emerging governance patterns. They never override repository truth or validated Master Archive state.

The current external governance signal strongly supports this separation: NIST's 2026 agent-identity work emphasizes identification, authorization, auditing, non-repudiation, and prompt-injection controls, while current control-plane research emphasizes deterministic enforcement outside the model's reasoning authority. ## Anti-drift law

The following are hard failures at a SAGE-owned boundary:

- treating conversation history as repository truth;
- claiming a live check without live evidence;
- accepting a stale branch/head as current truth;
- accepting model-generated authorization;
- allowing station identity to be supplied by an untrusted model output;
- projecting immersion as if it were canonical state;
- allowing a receipt to substitute for verification;
- allowing a passing test artifact to substitute for capability verification;
- allowing a session restoration path to bypass canonical rehydration;
- allowing any provider-specific adapter to create a second authority model.

## Jules continuity

Jules remains an execution multiplier, not an independent authority plane.

Every new Jules session must begin with:

`REPO TRUTH → CANONICAL IDENTITY → GOVERNANCE STATE → MISSION → EXECUTION → EVIDENCE → VERIFICATION → RECONVERGENCE`

Jules must emit the nameplate derived from her governed runtime identity. ChatGPT must not impersonate or supply it.

## Platform boundary

This doctrine can enforce behavior only where the conversation/exchange actually traverses a SAGE-owned runtime or integration boundary. A repository document cannot directly rewrite an unrelated standalone ChatGPT host session.

Therefore the doctrine's real success condition is runtime integration: **the interface must be routed through the governed SAGE boundary for the doctrine to become enforceable rather than merely descriptive.**

## Promotion gate

The doctrine itself is not proof of enforcement.

Promotion requires:

`IMPLEMENTATION → FOCUSED ADVERSARIAL TESTS → C2/RUNTIME TESTS → FULL PLATFORM TESTS → PRE-COMMIT → EXACT-HEAD CI → SHA RECONCILIATION → PROMOTION`

No synthetic completion. No receipt-as-truth. No authority through presentation.
