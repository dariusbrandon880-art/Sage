# SAGE Large-Build One-Shot Milestone Protocol

**Status:** governed operating protocol
**Authority:** SAGE canonical repository state
**Purpose:** permit large coherent jumps without weakening epistemic, safety, or verification gates.

## Core Rule

SAGE may pursue the largest coherent consequential frontier supported by verified state. Work is not artificially fragmented merely to reduce response or execution size. A long-running build may contain many dependent repairs, tests, observations, and promotions in one governed campaign.

**Longer execution is acceptable. Weaker evidence is not.**

## One-Shot Milestone Loop

`SENSE → RECON → SUPER SEARCH → BOUND → DECIDE → AUTHORIZE → BUILD → TEST → OBSERVE → REPAIR → RERUN → VERIFY → PROMOTE → COMPOUND`

The loop repeats automatically within the authorized frontier. A failure does not reset the campaign. It becomes evidence, its consequential cause is isolated, the smallest valid repair is applied, and the campaign resumes from the repaired state.

## Milestone Definition

A one-shot milestone is a bounded campaign that completes all connected work required to reach one consequential frontier, including:

- repository/context recon before changes;
- external challenge when external evidence can materially improve or falsify the decision;
- explicit scope and authority boundary;
- implementation of all coupled components required by the frontier;
- adversarial and regression tests;
- real execution/observation where the capability requires it;
- repair of discovered consequential defects;
- repeated verification until the frontier is either complete or genuinely blocked;
- durable evidence and a final classification.

## Failure Continuation Law

When a gate fails:

1. inspect the actual failure;
2. classify the failure as causal, environmental, instrumentation, or non-consequential;
3. use external evidence when it can challenge the diagnosis;
4. repair only the consequential boundary;
5. rerun the relevant focused tests;
6. rerun the complete affected gate;
7. continue toward the same milestone.

Do **not** manufacture green status, fabricate telemetry, erase negative results, or reopen unrelated architecture.

## Flight Integrity

For empirical milestones:

- baseline and SAGE execution remain symmetric;
- observations come from real execution;
- observation-only flights cannot mutate canonical state;
- missing telemetry is a hard verification failure;
- evaluator verdicts remain fail-closed;
- PASS requires sufficient evidence and independent verification;
- HOLD is mandatory for indeterminate evidence;
- NEGATIVE_RESULT is durable knowledge;
- capability qualification occurs only after earned evidence.

## Frontier Completion

A milestone is complete only when its intended observable capability is demonstrated or the frontier reaches a durable terminal classification:

`PASS | HOLD | NEGATIVE_RESULT`

A passing test suite alone is never a capability claim.

## Anti-Drift Constraints

Large-Build mode does **not** authorize:

- unrelated expansion;
- authority transfer to a model adapter;
- mutation of canonical state from observation-only experiments;
- suppression of failures;
- premature qualification;
- replacing repository truth with chat memory;
- delegating intelligence/recon that C2 can perform itself.

## Cross-Model Continuity

Model surfaces are interchangeable workers around canonical SAGE state. Provider/model output is proposal or evidence, never canonical authority. Station identity, mission, session, and state digest must reconcile before model output is accepted into governed state.

Canonical station identities:

- `[SAGE::DIRECTOR]` — authorization
- `[SAGE::C2::CHATGPT]` — intelligence, bounded decisions, independent verification
- `[SAGE::INTEL::GEMINI]` — recon and adversarial challenge
- `[SAGE::ENGINEER::JULES]` — engineering execution when explicitly involved

The protocol governs the runtime architecture; it does not claim to inject hidden instructions into proprietary chat products or rewrite arbitrary historical chats.

## Current Application

This protocol is attached to the longitudinal flight frontier. The immediate objective is to complete the real controlled flight, consume every actual failure, repair the flight boundary, verify the resulting evidence, and advance to the next consequential milestone without restarting the campaign.
